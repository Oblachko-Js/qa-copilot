# Критерии оценки AI-системы

## Бизнес-цель

Сократить время QA-инженера на подготовку тест-кейсов, не снижая покрытие рисков из требования.

Для проверки этой цели оценивается результат генерации для одного требования. Баллы по критериям ставятся по шкале от 1 до 5. В наборе требований результаты сравниваются по каждому критерию отдельно, а не сводятся к одному общему баллу.

## Наблюдаемые результаты и метрики

| Наблюдаемый результат | Критерий | Как измеряется | Связь с бизнес-целью |
|---|---|---|---|
| Значимые сценарии из требования присутствуют в ответе | Покрытие | Доля эталонных значимых сценариев, отражённых хотя бы в одном тест-кейсе | Хорошее покрытие снижает риск пропустить дефект и объём доработок после ревью |
| В кейсах нет неподтверждённых деталей | Точность и отсутствие галлюцинаций | Доля тест-кейсов без поведения, ограничений или условий, которых нет в требовании | Меньше исправлений и уточнений со стороны QA-инженера |
| Приоритеты соответствуют важности сценариев | Адекватность приоритета | Доля кейсов, приоритет которых совпадает с ожидаемым приоритетом по принятой оценке | Помогает QA-инженеру быстрее планировать и выполнять проверки |
| Кейсы понятны и готовы к использованию | Читаемость и готовность | Доля кейсов, принятых без существенных правок; дополнительно фиксируется время ревью | Чем меньше правок и короче ревью, тем меньше времени уходит на подготовку тестов |
| Ответ соответствует контракту API | Валидность схемы | Доля ответов, успешно разобранных в Pydantic-модель без нарушения ограничений схемы | Валидный ответ можно автоматически обработать и сохранить без ручной правки формата |

Для процентных показателей знаменатель должен быть больше нуля. Если в ответе нет тест-кейсов, это считается провалом для покрытия, точности и готовности, а не исключается из расчёта.

## Шкала оценки

Оценка содержания ставится на один ответ по шкале 1–5. Проценты в таблицах означают долю соответствующих элементов для этого требования.

### Покрытие сценариев

Покрытие = число эталонных значимых сценариев, отражённых в ответе / общее число эталонных значимых сценариев.

| Балл | Доля покрытия | Интерпретация |
|---|---:|---|
| 5 | 100% | Отражены все значимые сценарии, включая применимые негативные и граничные |
| 4 | 85–<100% | Покрыты основные сценарии; пропущен только один малозначительный сценарий |
| 3 | 70–<85% | Основные сценарии покрыты, но пропущен значимый граничный или негативный сценарий |
| 2 | 40–<70% | Покрыта только часть основных сценариев |
| 1 | <40% | Набор в основном не отражает риски требования или не содержит пригодных кейсов |

### Точность и отсутствие галлюцинаций

Кейс считается точным, если его ожидаемое поведение и предусловия подтверждаются требованием и он не добавляет неподтверждённую функциональность. Доля точных кейсов = число точных кейсов / общее число сгенерированных кейсов.

| Балл | Доля точных кейсов | Интерпретация |
|---|---:|---|
| 5 | 100% | Выдуманных деталей нет |
| 4 | 90–<100% | Есть только одна несущественная неподтверждённая деталь |
| 3 | 75–<90% | Есть неподтверждённые детали, но основное поведение соответствует требованию |
| 2 | 50–<75% | Выдуманные детали существенно влияют на часть тест-кейсов |
| 1 | <50% | Значительная часть ответа основана на неподтверждённой или противоречащей требованию функциональности |

### Адекватность приоритета

Приоритеты сравниваются с ожидаемыми значениями, установленными при оценке требования. Доля совпадений = число кейсов с подходящим приоритетом / общее число кейсов.

| Балл | Доля совпадений | Интерпретация |
|---|---:|---|
| 5 | 100% | Все приоритеты адекватны важности сценариев |
| 4 | 85–<100% | Есть одно небольшое расхождение, не влияющее на критичные проверки |
| 3 | 70–<85% | Основные приоритеты адекватны, но одна важная проверка недооценена или переоценена |
| 2 | 40–<70% | Значительная часть приоритетов не соответствует важности сценариев |
| 1 | <40% | Приоритеты в основном неадекватны или отсутствуют |

### Читаемость и готовность к использованию

Кейс считается готовым, если его можно передать в работу без изменения смысла, добавления шагов или уточнения ожидаемого результата. Доля готовых кейсов = число кейсов, принятых без существенных правок / общее число кейсов.

| Балл | Доля готовых кейсов | Интерпретация |
|---|---:|---|
| 5 | 100% | Все кейсы понятны и сразу пригодны к использованию |
| 4 | 85–<100% | Нужны только незначительные стилистические правки |
| 3 | 70–<85% | Основные кейсы пригодны, но некоторые требуют уточнения или доработки |
| 2 | 40–<70% | Большинству кейсов нужны существенные правки |
| 1 | <40% | Ответ трудно понять или почти все кейсы нужно переписать |

### Валидность схемы

Для одного ответа результат бинарный: он либо проходит проверку `TestCaseList`, либо нет. Для набора требований метрика считается как число ответов, успешно разобранных по схеме, / общее число попыток генерации.

| Балл | Доля валидных ответов |
|---|---:|
| 5 | 100% |
| 4 | 95–<100% |
| 3 | 85–<95% |
| 2 | 70–<85% |
| 1 | <70% |

Промежуточный балл по валидности не отменяет обязательного порога: для принятия результата все ответы проверочного набора должны пройти валидацию.

## Пороговые значения

- **Минимально необходимый результат:** не менее 3 баллов по каждому критерию и 100% ответов, прошедших проверку JSON-схемы.
- **Целевой результат:** не менее 4 баллов по каждому критерию и отсутствие существенных ручных правок на типовых требованиях.

Критерии покрытия и точности показывают, насколько тест-кейсы сохраняют смысл требования; вместе с готовностью к использованию они помогают оценивать трудозатраты QA на ревью. Валидность схемы отдельно показывает, можно ли автоматически обрабатывать ответы приложения.
