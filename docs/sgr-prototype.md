# Прототип Schema-Guided Reasoning

## Цель

Проверить двухшаговую генерацию тест-кейсов: сначала модель структурированно
анализирует требование, затем формирует кейсы по кандидатам в сценарии.
Промежуточный анализ проверяется отдельно и сохраняется вместе с результатом.

## Реализация

В [скрипте прототипа](../scripts/run_sgr_prototype.py) описаны две Pydantic-схемы:

- `RequirementAnalysis`: ключевые сущности, ограничения, неоднозначности и
  список сценариев;
- `ScenarioCandidate`: описание сценария, тип (`positive`, `negative` или
  `boundary`) и краткое объяснение риска.

Первый вызов использует `response_format=RequirementAnalysis`. Второй получает
исходное требование и прошедший проверку анализ и использует
`response_format=TestCaseList` из приложения. Результат второго вызова должен
содержать по одному тест-кейсу на каждый сценарий, выбранный в пределах
`max_cases`; несоответствие количества вызывает явную ошибку.

Валидация Pydantic проверяет структуру, обязательные поля, непустые значения
и допустимые типы сценариев. Это позволяет отдельно просмотреть и проверить
промежуточный результат вместо разбора свободного текста регулярными
выражениями. Валидация схемы сама по себе не доказывает правильность смысла.

## Запуск локально

Убедитесь, что Ollama запущена и модель `qwen2.5:7b` установлена. В терминале
из корня проекта выполните:

```bash
source .venv/bin/activate
export LLM_BASE_URL=http://localhost:11434/v1
export LLM_API_KEY=ollama
export LLM_MODEL=qwen2.5:7b
python -m scripts.run_sgr_prototype \
  --output evaluation/sgr-example.json
```

Для внешнего OpenAI-совместимого провайдера задайте его `LLM_BASE_URL`,
`LLM_API_KEY` и `LLM_MODEL`. Прототип делает два последовательных запроса;
при платном провайдере это увеличит расход и задержку относительно одного
вызова.

## Пример полного прогона

- **Требование:** если сумма товаров составляет 5000 рублей или больше,
  доставка бесплатна; если сумма меньше 5000 рублей, стоимость доставки
  составляет 300 рублей.
- **Промежуточный результат:** модель выделила сущности и оба пороговых
  правила, затем предложила пять сценариев. Среди них — 5000, 4999, 5001,
  2999 и 3000 рублей.
- **Финальный результат:** второй вызов сформировал пять тест-кейсов, каждый
  прошёл `TestCaseList`.
- **Полный вход, анализ и результат:** сохранены в
  [sgr-example.json](../evaluation/sgr-example.json). Прогон выполнен локально
  на `qwen2.5:7b` при температуре `0.2`.

В этом примере модель ошибочно назвала значение 5000 рублей неоднозначным и
пометила соответствующий сценарий как `negative`, хотя требование явно
предписывает бесплатную доставку при сумме от 5000 рублей. На этапе генерации
модель вернула правильный ожидаемый результат для этого кейса, следуя
исходному требованию. Этот пример показывает ограничение подхода: схема делает
ошибки промежуточного анализа видимыми для проверки, но не гарантирует
семантическую правильность. Перед использованием результат нужно проверить.

## Проверки

Тесты в [test_sgr_prototype.py](../tests/test_sgr_prototype.py) проверяют, что
выполняются два последовательных вызова с соответствующими Pydantic-схемами,
недопустимый тип сценария отклоняется, а превышение ожидаемого количества
кейсов приводит к явной ошибке.
